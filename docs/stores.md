# Публикация в магазинах расширений

Проверено по документации Chrome Web Store и Mozilla 22 сентября 2026 года. Подготовка файлов не означает одобрения модерацией. Основные цели — Chrome Web Store и Firefox Add-ons (AMO); отдельная проверка Edge Add-ons в эту подготовку не входит.

## Подготовка файлов

Из корня репозитория, Node.js 22+:

```bash
npm ci --prefix extensions/browser/runet-censorship-bypass
npm run lint
npm test
npm run store:package
npm run lint:firefox
npm run test:browser:chrome
npm run store:screenshots
```

В `store-artifacts/v<version>/` появятся:

| Файл | Назначение |
| --- | --- |
| `anticheburnet-v<version>-chromium-store.zip` | Загрузка в Chrome Web Store, `manifest.json` лежит в корне |
| `anticheburnet-v<version>-firefox-store.zip` | Загрузка в AMO для публичного размещения |
| `anticheburnet-v<version>-sources.zip` | Исходники и инструкции для проверяющего Mozilla |
| `*.sha256` | Контрольные суммы ZIP |
| `images/` | Скриншоты настоящего интерфейса, промоизображение и иконка |

Архив исходников содержит только явно перечисленные входные файлы проекта. Он включает незакоммиченные изменения, но не `.git`, `node_modules`, локальные профили браузера и секреты. Его надо формировать заново после любых изменений. Скриншоты создаются в отдельном временном профиле Chrome с отключёнными внешними сетевыми обращениями, без пользовательских данных. При нестандартной установке браузера задайте `CHROME_BIN`.

CI также создаёт эти три ZIP и сохраняет их в артефакте `store-submissions` после успешных проверок. Автоматической отправки в магазины нет.

## Текст карточки

Название: **АнтиЧебурнет**.

Краткое описание: **Выборочная маршрутизация сайтов через PAC и собственные прокси.**

Полное описание для копирования:

> АнтиЧебурнет управляет прокси-настройками браузера и направляет выбранные сайты через PAC или собственные прокси.
>
> • PAC-источники «Антизапрет» и «Антицензорити», собственный PAC по ссылке и режим своих сайтов.
> • Правила для отдельных доменов: через прокси, напрямую или по PAC.
> • HTTP, HTTPS, SOCKS4/SOCKS5, локальные Tor и WARP. Для HTTP/HTTPS-прокси поддерживаются логин и пароль.
> • Проверка прокси, локальный журнал диагностики и импорт/экспорт списков доменов.
> • Проверка домена в сервисе Роскомнадзора с ручной CAPTCHA и отправкой; команды открытия страницы в веб-архиве и переводчике.
>
> Интерфейс настроек — на русском языке. Это не системный VPN: расширение влияет на браузерный трафик и не гарантирует анонимность или доступность любого сайта. Для собственных прокси, Tor и WARP нужен отдельно настроенный сервис.
>
> Настройки и журнал хранятся локально; автоматической аналитики нет. PAC загружается с выбранного источника, а выбранный трафик проходит через сторонние прокси. Их операторы видят адреса назначения и метаданные соединений; незашифрованный HTTP может раскрывать содержимое. Учётные данные передаются соответствующему прокси для авторизации. Команды внешних сервисов передают им URL или домен страницы. Подробнее — в политике приватности.
>
> В Firefox требуется разрешить работу в приватных окнах: настройка прокси действует на весь профиль. Приватные запросы не сохраняются в статистике вкладок и журнале запросов.

Главная страница: `https://github.com/xSoDx-stack/runet-censorship-bypass`.
Поддержка: `https://github.com/xSoDx-stack/runet-censorship-bypass/issues`.
Политика приватности после пуша: `https://github.com/xSoDx-stack/runet-censorship-bypass/blob/development/PRIVACY.md`.
До отправки убедитесь, что ссылка доступна без входа в GitHub. Контактный email и сведения об издателе в кабинетах указывает владелец аккаунта; email исходного проекта в старых метаданных нельзя выдавать за свою службу поддержки.

## Chrome Web Store: Privacy practices

Единственная цель (Single purpose): выборочная маршрутизация браузерного трафика через PAC и пользовательские прокси, включая управление правилами и диагностику этой маршрутизации.

| Разрешение | Обоснование для проверяющего |
| --- | --- |
| `proxy` | Установить, восстановить или отключить PAC в настройках браузера |
| `alarms` | Периодическое обновление выбранного PAC |
| `storage` | Локальные настройки, доменные правила и диагностика |
| `unlimitedStorage` | Сохранение больших PAC (до 25 МиБ для встроенных источников), их обработанных копий и правил |
| `tabs` | Получить URL текущей вкладки для доменного правила, проверки реестра и индикации маршрута |
| `contextMenus` | Команды для выбранной страницы: реестр, архив и переводчик |
| `notifications` | Уведомления об ошибках PAC и потере контроля над прокси |
| `webRequest` | Локальная диагностика ошибок и определение использованного прокси; тела запросов и ответов не читаются |
| `webRequestAuthProvider` | Передача настроенного логина и пароля соответствующему прокси, без вмешательства в авторизацию сайтов |
| `<all_urls>` | Работа диагностики и авторизации на произвольных сайтах, загрузка пользовательского PAC и проверка прокси |

Раздел обработки данных заполняйте по фактическому использованию, а не по наличию аналитики: расширение обрабатывает адреса сайтов и учётные данные прокси, передаёт URL внешним сервисам по команде, а браузер — трафик выбранным прокси. Не заявляйте «никакие данные не обрабатываются и не передаются». Для полей о Web history / Authentication information укажите эти функции и отсутствие продажи/рекламного использования. Уточняйте названия категорий по текущей форме магазина.

Remote code: все скрипты интерфейса и фонового обработчика упакованы локально. Отдельно раскройте загрузку PAC — это JavaScript маршрутизации, который выполняет встроенный PAC-движок браузера через `proxy.settings`, а не контекст расширения. Приложите объяснение из `reviewer-notes.md`. Не заявляйте, что PAC — просто JSON или что магазин гарантированно допускает такую схему: её оценка остаётся за модератором.

Для карточки подготовлены PNG 1280×800 и небольшое промоизображение 440×280. Не используйте скриншоты Chromium как доказательство проверки интерфейса Firefox: для AMO они иллюстрируют общий интерфейс, а реальную работу Firefox нужно проверить отдельно.

## Firefox Add-ons

В AMO выберите размещение **On this site** и загрузите `firefox-store.zip`, затем архив исходников и текст из `reviewer-notes.md`. Укажите лицензию GPL-3.0-or-later, описание и политику приватности.

Команда `npm run sign:firefox` и действующий GitHub Release используют канал **unlisted** — подпись для самостоятельного распространения. Это не публикация в каталоге AMO. Не переключайте существующий workflow на `listed` без настройки карточки. Если данная версия уже отправлена в AMO или подписана, проверьте допустимость повторной подачи и при необходимости увеличьте версию, затем пересоберите все файлы.

Манифест заявляет передачу `browsingActivity` (URL/домены для сетевых функций) и `authenticationInfo` (прокси-авторизация). Это не декларация аналитики разработчика. При обновлении Firefox может запросить согласие на новые категории. Минимальные версии 140 для Desktop и 142 для Android обеспечивают встроенное согласие Firefox.

Перед подачей вручную проверьте Firefox: установку, согласие, разрешение приватных окон, применение PAC, собственный прокси с авторизацией, отключение, перезапуск браузера и отсутствие приватных доменов в журнале. Firefox Android пока только заявлен в манифесте; не выбирайте Android в карточке без проверки на устройстве.
